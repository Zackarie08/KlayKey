# UI and compact-model release — 18 October 2026

The builder now mounts the existing Three.js engine directly in the storefront document. The previous iframe loaded a separate viewport-height viewer with a scrolling configuration sidebar; the replacement is a responsive grid with a sticky preview and naturally scrolling options. It shares the storefront header, footer, typography, forms and toasts. There is no iframe, object or embed in the builder, and no vertically scrolling configuration panel.

The shared scale uses 16 px body text, 14 px labels, 16 px inputs, 14–15 px navigation, 15 px buttons and responsive headings. Metadata is at least 13 px. Containers, form spacing, card alignment, touch targets, authentication headings, empty states and action copy were refined. Steps are clickable section links with active/completed indicators; defaults provide complete valid choices. Typing uses one Start/Stop toggle, Escape exits, and touch rotation requires an explicit interaction toggle so document scrolling stays available.

The procedural 60% source no longer extends the chassis for controls. Case, bottom, plate, PCB, gasket, feet and screw placement follow the compact dimensions. Its USB-C position remains proportional to the case. Regenerated Blender source, GLB, preview, manifest and layout metadata pass validation. The 60% is **300.75 × 110.25 mm**, approximate assembled height **39.6 mm**, with **61 keys**. GLB size: **8,712,216 bytes**. No control-bay, knob or display nodes remain. The 75% and 100% GLBs and Blender sources are unchanged.

Compatibility schema 3 removes both knob and display from 60%. Shared normalization handles layout changes and old saved builds, recalculates component pricing and supplies a readable notice. Reads do not rewrite saved configurations; explicit saves persist the new configuration. Cart snapshots also normalize before checkout. Historical order snapshots remain unchanged. No database migration or bulk data rewrite is needed.

Validation: 15 commerce/production tests and 10 asset tests passed; all three GLBs have zero validator errors and warnings. The local browser interaction suite passed **268/268**, including all layouts, physical-key animation, audio profiles and larger-layout knob behavior. The count is five lower than the previous release because unsupported 60% control checks were removed. The 60% preview was visually inspected after Blender regeneration and in the website.

All 17 requested customer page types were measured at **360, 390, 768, 1024, 1366, 1440 and 1920 px**. Across 133 page/state measurements (including empty and populated cart/history states), no horizontal page overflow or sub-13 px checked body/label text was found. Builder checks found zero embedded documents and zero nested vertical scrollers at every width. Browser workflows verified login, logout, a 60% layout transition and price update, physical typing and stop, save, add to cart and simulated checkout with confirmation. Desktop/mobile screenshots were inspected for major pages; this is Chromium emulation, not physical-device or Safari/Firefox certification.

Only the existing KlayKey web service is intended to redeploy from this release. Payments remain simulated. Cross-browser, physical-device, load and subjective acoustic tests remain outside the completed checks.

Live verification found that returning browsers could reuse the prior standalone viewer module from its one-hour cache. The native integration now versions its entry module, changed dependencies and manifest to invalidate those existing cache entries; future viewer script responses use no-store. The resize callback also tolerates a removed viewport.
